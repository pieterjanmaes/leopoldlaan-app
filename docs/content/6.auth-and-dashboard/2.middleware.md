---
title: Route middleware
description: Auth and role guards applied per page via definePageMeta.
---

## `auth.ts` — require login

```ts [app/middleware/auth.ts]
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn } = useUserSession();

  if (!loggedIn.value) {
    return navigateTo('/dashboard/login');
  }
});
```

Apply on any page that requires a logged-in user:

```vue [app/pages/dashboard/index.vue]
<script setup lang="ts">
definePageMeta({
  layout: 'dashboard',
  middleware: 'auth'
});
</script>
```

## `superadmin.ts` — require superadmin role

```ts [app/middleware/superadmin.ts]
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn, user } = useUserSession();

  if (!loggedIn.value) {
    return navigateTo('/dashboard/login');
  }
  if (user.value?.role !== 'superadmin') {
    return navigateTo('/dashboard');
  }
});
```

Apply on superadmin-only pages:

```vue [app/pages/dashboard/users.vue]
<script setup lang="ts">
definePageMeta({
  layout: 'dashboard',
  middleware: 'superadmin'
});
</script>
```

`superadmin` already includes the auth check — don't stack both.

## Combining middleware

If you ever need both `auth` and another check (e.g. `team-member`), pass an array:

```ts
definePageMeta({
  middleware: ['auth', 'team-member']
});
```

They run in array order.

## Why middleware AND server-side checks?

Middleware protects the **UI** — the dashboard page won't render for unauthorized users. But server-side endpoints still need their own checks:

```ts [server/api/users/[id].delete.ts]
import { requireUserSession } from '#auth-utils';

export default defineEventHandler(async (event) => {
  const { user } = await requireUserSession(event);
  if (user.role !== 'superadmin') {
    throw createError({ statusCode: 403, message: 'Forbidden' });
  }
  // ... delete the user
});
```

Without the server check, a determined attacker could call the API directly with a valid session cookie of a non-superadmin user and the middleware wouldn't help.

**Rule of thumb**: middleware guards the page render, server guards the data mutation. Always both.
