## Layout

`app/layouts/dashboard.vue` wraps every dashboard page in a `<UDashboardGroup>` with a sidebar that has nav items + a footer with the signed-in user's email and a logout button.

```vue [app/layouts/dashboard.vue (simplified)]
<UDashboardGroup>
  <UDashboardSidebar>
    <template #default>
      <UNavigationMenu :items="navigationItems" orientation="vertical" />
    </template>
    <template #footer>
      <UAvatar :alt="user?.email" />
      <span>{{ user?.email }}</span>
      <UButton icon="i-lucide-log-out" @click="onLogout" />
    </template>
  </UDashboardSidebar>

  <slot />
</UDashboardGroup>
```

## Existing pages

| Page | URL | Middleware | Purpose |
|---|---|---|---|
| `pages/dashboard/index.vue` | `/dashboard` | `auth` | Form submissions list + CSV/Excel export |
| `pages/dashboard/users.vue` | `/dashboard/users` | `superadmin` | User CRUD |
| `pages/dashboard/login.vue` | `/dashboard/login` | — | Sign-in form (uses `login` layout, not `dashboard`) |

## The nav items array

```ts
const navigationItems = computed(() => {
  const items = [
    {
      label: 'Form Submissions',
      icon: 'i-lucide-inbox',
      to: '/dashboard'
    }
  ];

  if (user.value?.role === 'superadmin') {
    items.push({
      label: 'Users',
      icon: 'i-lucide-users',
      to: '/dashboard/users'
    });
  }

  return items;
});
```

The "Users" entry only appears for superadmins. Role-conditional items go here.

## Adding a new dashboard page

1. **Create the page** under `app/pages/dashboard/`:

   ```vue [app/pages/dashboard/settings.vue]
   <template>
     <UDashboardPanel>
       <UDashboardNavbar title="Settings" />
       <UDashboardPanelContent>
         <!-- your UI -->
       </UDashboardPanelContent>
     </UDashboardPanel>
   </template>

   <script setup lang="ts">
   definePageMeta({
     layout: 'dashboard',
     middleware: 'auth' // or 'superadmin'
   });
   </script>
   ```

2. **Add a nav item** in `dashboard.vue`:

   ```ts
   items.push({
     label: 'Settings',
     icon: 'i-lucide-settings',
     to: '/dashboard/settings'
   });
   ```

3. If the API endpoints need auth too, use `requireUserSession` in the server handler — see [Sessions](/auth-and-dashboard/sessions).

## Why the `/` button in the sidebar header goes to dashboard root

The sidebar header has a "Home" button that navigates to `/dashboard` (not the website's `/`). Going to `/` would redirect to `/nl` (rootRedirect) which would feel wrong from inside the admin UI.

## i18n in the dashboard

The dashboard is currently rendered with i18n routing — URLs are `/nl/dashboard`, `/fr/dashboard`, etc. If you want the dashboard to live at a single non-localized URL (`/dashboard`):

```ts
definePageMeta({
  layout: 'dashboard',
  middleware: 'auth',
});

// Opt this route out of i18n
defineI18nRoute(false);
```

But be aware that `navigateTo` calls inside the dashboard will still try to add a locale prefix unless you use `localePath()` workarounds. For now, the project accepts the prefixed dashboard URLs.
