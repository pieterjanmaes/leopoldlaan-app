## Stack

- **`nuxt-auth-utils`** — session cookies, hashing helpers, server-side session validation
- **scrypt** for password hashing (built into `nuxt-auth-utils`)
- **Session cookie** encrypted with `NUXT_SESSION_PASSWORD` (32+ random chars)

## Logging in

`POST /api/auth/login` validates email + password against the `users` table and sets a session cookie:

```ts [server/api/auth/login.post.ts (simplified)]
import { db } from 'hub:db';
import { users } from '~~/server/db/schema';
import { verifyPassword, setUserSession } from '#auth-utils';

export default defineEventHandler(async (event) => {
  const { email, password } = await readBody(event);

  const user = await db.select().from(users).where(eq(users.email, email)).get();
  if (!user || !(await verifyPassword(user.password, password))) {
    throw createError({ statusCode: 401, message: 'Invalid credentials' });
  }

  await setUserSession(event, {
    user: { id: user.id, email: user.email, role: user.role, name: user.name }
  });

  return { success: true };
});
```

## Reading the session in components

```vue
<script setup lang="ts">
const { user, loggedIn, clear: logout } = useUserSession();
</script>

<template>
  <div v-if="loggedIn">
    Signed in as {{ user?.email }}
    <UButton @click="logout">Sign out</UButton>
  </div>
</template>
```

`useUserSession()` is auto-imported. `user` is reactive and updates when the session changes.

## Reading the session on the server

```ts
import { requireUserSession } from '#auth-utils';

export default defineEventHandler(async (event) => {
  const { user } = await requireUserSession(event);
  // user.id, user.email, user.role, user.name are typed
  return { hello: user.email };
});
```

`requireUserSession` throws a 401 if the user isn't logged in. Use `getUserSession` if you want to handle the unauthenticated case yourself.

## Logging out

```ts
// Server: clear the session cookie
await clearUserSession(event);

// Client (Vue):
const { clear } = useUserSession();
await clear();
```

## Roles

Two roles defined in the schema enum:

| Role | Access |
|---|---|
| `admin` | `/dashboard` (form submissions list + export) |
| `superadmin` | Everything above + `/dashboard/users` (user management) |

Role checks happen in two places:
- **Middleware** (`auth.ts`, `superadmin.ts`) — redirects the user before the page renders
- **Server endpoints** — explicit `if (user.role !== 'superadmin') throw ...` in routes that mutate users

See [Middleware](/auth-and-dashboard/middleware) for the redirect logic.

## Hashing passwords

When creating users (registration, seed, reset):

```ts
import { hashPassword } from '#auth-utils';

const hashed = await hashPassword('plaintext-password');
// store `hashed` in the users.password column
```

When verifying (login):

```ts
import { verifyPassword } from '#auth-utils';

const ok = await verifyPassword(user.password, plaintextAttempt);
```

The hash format is scrypt with a salt prepended; `verifyPassword` handles parsing.

## Session lifetime

The cookie is signed with `NUXT_SESSION_PASSWORD` and has a default lifetime of 1 week (rolling). You can tune this in `nuxt.config.ts` under `runtimeConfig.session.maxAge` if needed — see the [nuxt-auth-utils docs](https://github.com/atinux/nuxt-auth-utils#configuration).
