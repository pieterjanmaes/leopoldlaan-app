## What Turnstile is

[Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/) is a CAPTCHA replacement — instead of asking users to identify traffic lights, it runs invisible browser challenges. Most legitimate users see nothing; suspected bots get blocked.

## Setup

Two keys per environment:

| Key | Visibility | Purpose |
|---|---|---|
| `NUXT_PUBLIC_TURNSTILE_SITE_KEY` | Public | Embedded in the client widget |
| `NUXT_TURNSTILE_SECRET_KEY` | Server-only | Used to verify the token server-side |

## Client side

The widget is rendered with `<NuxtTurnstile>` (from `@nuxtjs/turnstile`):

```vue [app/pages/login.vue (excerpt)]
<template #validation>
  <NuxtTurnstile ref="turnstile" v-model="captchaToken" class="mt-2" />
</template>
```

The login page waits for the token before submitting and resets the widget after a failed attempt.

When the challenge passes, `captchaToken` populates with a short-lived token. Submit it with the form.

## Server side

`server/api/auth/login.post.ts` verifies the token before it looks at the credentials:

```ts
const body = await readValidatedBody(event, (body) => loginSchema.parse(body));

if (!(await verifyTurnstileToken(body.captchaToken))) {
  throw createError({ statusCode: 400, message: 'Captcha-verificatie mislukt, probeer opnieuw' });
}
```

`verifyTurnstileToken` posts to Cloudflare's `siteverify` endpoint with `NUXT_TURNSTILE_SECRET_KEY` and returns a boolean.

## Test keys for local dev

Cloudflare provides always-pass and always-fail test keys for development:

```bash
NUXT_PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA          # always passes
NUXT_TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA    # always succeeds
```

The full list is in [Cloudflare's testing docs](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

`.env.example` ships with these test keys so login works out of the box on a fresh clone.

## Production setup

1. Go to `dash.cloudflare.com → Turnstile → Add Site`
2. Add your domain(s) — separate site keys per environment (preview vs production) is fine
3. Get the public site key → set as **GitHub Actions repo variable** `NUXT_PUBLIC_TURNSTILE_SITE_KEY`
4. Get the secret key → set as **Cloudflare Wrangler secret**:
   ```bash
   wrangler secret put NUXT_TURNSTILE_SECRET_KEY
   wrangler secret put NUXT_TURNSTILE_SECRET_KEY --env preview
   ```
5. Deploy — verification will use the real Turnstile servers

## When Turnstile blocks legitimate users

Cloudflare's challenge can be sticky for users on:
- Privacy-focused VPNs
- Tor
- Old browsers without WebGL

If users complain, check the Turnstile analytics dashboard for the false-positive rate. Cloudflare offers different challenge modes (managed / non-interactive / invisible) — adjust per-widget if needed.
