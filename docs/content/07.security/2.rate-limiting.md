---
title: Rate limiting
description: Per-IP limits on the API, tighter on authentication.
---

The global limiter is off (`security.rateLimiter: false`); limits are set per route in `routeRules`:

```ts
routeRules: {
  '/api/**': {
    security: { rateLimiter: { tokensPerInterval: 240, interval: 60_000 } }
  },
  // Credential endpoints get a much tighter budget against brute forcing.
  '/api/auth/**': {
    security: { rateLimiter: { tokensPerInterval: 10, interval: 60_000 } }
  }
}
```

| Route | Limit | Why |
|---|---|---|
| `/api/**` | 240 / minute / IP | A dashboard page makes several calls at once (tasks, lookups, project, Drive thumbnails); the starter's 10/min was far too tight |
| `/api/auth/**` | 10 / minute / IP | Login and register — slows down password guessing |

Pages, `/auth/google-drive` and static assets aren't limited.

## Caveat on Workers

nuxt-security's limiter keeps counters in memory, per Worker isolate. On Cloudflare a client can hit several isolates, so treat these limits as a speed bump, not a guarantee. For a hard limit, add a [Cloudflare WAF rate-limiting rule](https://developers.cloudflare.com/waf/rate-limiting-rules/) on `/api/auth/*`.
