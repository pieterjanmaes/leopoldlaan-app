---
title: Project structure
description: Where things live in the Nuxt 4 layout.
---

```
app/
  components/      C-prefixed components (CPage, CKanban, CGantt, CFloorPlanCanvas, …)
  composables/     useAction, useLookups, useTasks, useDriveUpload, …
  layouts/         default (dashboard shell), auth (login/register)
  middleware/      auth.global (login required), internal (household only)
  pages/           one file per screen: index, taken, planning, grondplan, budget, bestanden, …
  plugins/         vueKonva.client, userback.client, scrollBehavior.client
  utils/           nav, format (dates, bytes, Drive URLs), colors (canvas hex values)
server/
  api/             REST endpoints, file name = route + method (e.g. tasks/[id].patch.ts)
  db/              schema.ts and drizzle-kit migrations
  plugins/         session re-validation
  routes/auth/     Google Drive OAuth callback
  utils/           auth, tasks, budget, drive, attachments, invites, crypto, floorPlans, …
shared/
  schemas/         Zod input schemas, used by forms and endpoints
  types/           API response shapes (api.ts) and session typing
  utils/           constants, money, vat, dates, budget, dependencies, geometry, permissions
test/
  unit/            plain Node tests (logic, server helpers)
  nuxt/            component tests in a Nuxt environment
docs/              this site (Docus)
presentation/      Slidev deck from the starter
```

`shared/utils` and `shared/types` are auto-imported on both sides (app and server). Server files import them with explicit relative paths so they also work in plain-Node unit tests.
