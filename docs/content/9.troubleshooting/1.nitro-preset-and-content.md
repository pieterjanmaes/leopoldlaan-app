title: Blank page after language switch
description: Or "Nuxt Studio sidebar empty" — both have the same root cause.
---

## Symptoms

Both of these have the same cause:

- **Initial page load works** (e.g. `/nl/cookie-policy` renders fine via SSR)
- **Clicking the language switcher** changes the URL to `/fr/cookie-policy` but the page goes **blank** (no content rendered, no 404)
- **Nuxt Studio sidebar is empty** — no collections listed

## Diagnosis

Curl the client-side content endpoint:

```bash
curl -ks -o /dev/null -w "%{size_download}\n" "https://localhost:3000/__nuxt_content/content_fr/sql_dump.txt"
```

If it returns **`0`**, the client-side content DB is empty. SSR works because it reads D1 directly through the binding; client-side queries fetch this dump and get nothing.

## Root cause

`@nuxt/content`'s **cloudflare** sub-preset registers a `/__nuxt_content/{collection}/sql_dump.txt` handler that expects a Cloudflare `ASSETS` binding. In dev there's no `ASSETS`, and the fallback storage key doesn't resolve to the actual files at `.nuxt/content/raw/dump.content_*.sql`. Handler returns `""`, client DB stays empty, `queryCollection(...).first()` returns `null`, page goes blank.

This is triggered by `nitro.preset: 'cloudflare_module'` being active during `nuxt dev` (which Nuxt Content's module detects).

## Fix

`nuxt.config.ts` sets the Nitro preset **conditionally** so dev uses the default (node) preset:

```ts
nitro: {
  preset: process.env.NODE_ENV === 'development' ? undefined : 'cloudflare_module',
  // ...
}
```

With the preset unset in dev, `@nuxt/content` registers its node sub-preset, which reads the SQL dump from filesystem. The `cloudflare_module` preset stays active for `pnpm run build`.

## Verify the fix

```bash
# After restart, the dump endpoint should return non-zero bytes
curl -ks -o /dev/null -w "%{size_download}\n" "https://localhost:3000/__nuxt_content/content_fr/sql_dump.txt"
# → expect a number > 0
```

Then in the browser, switch language — content should switch too.

## Why the issue only appears in dev

In production deployed to Cloudflare Workers, the `ASSETS` binding IS available, so the cloudflare sub-preset's handler works correctly. The bug is dev-specific.

If you ever change the preset back to always-on `cloudflare_module`, you'll re-introduce this problem.
