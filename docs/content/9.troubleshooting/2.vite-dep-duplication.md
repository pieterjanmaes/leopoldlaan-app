---
title: Vue duplication / "Cannot read properties of null (reading 'ce')"
description: Why optimizeDeps.include alone is not enough; you also need resolve.dedupe.
---

## Symptoms

- The page renders briefly, then crashes with a console error:
  ```
  TypeError: Cannot read properties of null (reading 'ce')
    at renderSlot (runtime-core.esm-bundler.js?v=f7faa647:3267:32)
    at Proxy.<anonymous> (ConfigProvider.js?v=54802482:47:11)
  ```
- Note the **two different `?v=` hashes** in the stack — that's the smoking gun: **two copies of Vue are loaded simultaneously**.
- Hydration mismatches and "Vue warn: Unhandled error" follow.

## Root cause

`@vue/devtools-core` and `@vue/devtools-kit` (loaded by Nuxt DevTools) depend on `vue`. When Vite pre-bundles them via `optimizeDeps`, it can pull in a second Vue copy — separate from the one Nuxt itself uses. Vue's internal context (`ctx.ce`) is null in components that load via the wrong copy.

## Fix

`nuxt.config.ts` ships with both `optimizeDeps.include` AND `resolve.dedupe`:

```ts
vite: {
  resolve: {
    dedupe: ['vue']
  },
  optimizeDeps: {
    include: ['@unhead/schema-org/vue', '@userback/widget', '@vue/devtools-core', '@vue/devtools-kit', 'zod', 'zod/locales']
  }
}
```

`resolve.dedupe: ['vue']` forces Vite to resolve every `import 'vue'` to the same module instance, regardless of which package requested it.

## Adding a new pre-bundle entry

When Vite logs:

```
ℹ Vite discovered new dependencies at runtime:
  some-new-package ← ./app/plugins/whatever.ts
Pre-bundle them in your nuxt.config.ts to avoid page reloads
```

Add the package to `vite.optimizeDeps.include`. The `resolve.dedupe` is already in place, so you won't re-introduce the Vue-duplication bug.

```ts
vite: {
  resolve: { dedupe: ['vue'] },
  optimizeDeps: {
    include: [
      'some-new-package',  // new entry
      '@unhead/schema-org/vue',
      '@userback/widget',
      '@vue/devtools-core',
      '@vue/devtools-kit',
      'zod',
      'zod/locales'
    ]
  }
}
```

## When `resolve.dedupe` isn't enough

If you still see duplicate Vue (or other peer dep) issues:
1. Run `pnpm why vue` — see which packages depend on Vue
2. Check for packages that bundle Vue rather than declaring it as a peer dep — those won't dedupe
3. As a nuclear option, add `optimizeDeps.exclude` for the misbehaving package

## Why this is dev-only

Vite pre-bundling only happens in `nuxt dev`. The production build uses Rollup which handles deduplication via tree shaking. So this issue never appears in deployed environments.
