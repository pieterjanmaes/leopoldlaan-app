## The split

Three tools, each with a narrow job:

| Tool | Role | Config |
|---|---|---|
| **Oxlint** | Fast Rust-based linter — covers most ESLint rules | `oxlint.config.ts` |
| **Oxfmt** | Fast Rust-based formatter (Prettier-style) | `oxfmt.config.ts` |
| **ESLint** | Vue-specific stylistic rules Oxlint doesn't have | `eslint.config.mjs` |

This split keeps the slow ESLint runs scoped to a small ruleset; everything else runs through Oxlint at >10× the speed.

## Shared config: `@wotzebra/oxc-config`

The rules don't live in this repo. They come from the shared [`wotzebra/oxc-config`](https://github.com/wotzebra/oxc-config) package, installed straight from GitHub:

```json [package.json]
"@wotzebra/oxc-config": "github:wotzebra/oxc-config"
```

Each project config file only passes what differs from the shared base:

::code-group
```ts [oxlint.config.ts]
import { oxlintConfig } from '@wotzebra/oxc-config/oxlint';

import { withNuxt } from './.nuxt/oxlint.mjs';

export default withNuxt(oxlintConfig());
```

```ts [oxfmt.config.ts]
import { oxfmtConfig } from '@wotzebra/oxc-config/oxfmt';

export default oxfmtConfig({
	ignorePatterns: ['server/db/migrations']
});
```

```js [eslint.config.mjs]
import { eslintConfigs } from '@wotzebra/oxc-config/eslint';

import withNuxt from './.nuxt/eslint.config.mjs';
import oxlint from './oxlint.config.ts';

export default withNuxt(...eslintConfigs({ oxlint }));
```
::

How overrides merge:
- **`oxlintConfig(overrides)`** — arrays (`ignorePatterns`, `overrides`, `jsPlugins`) are appended; objects (`rules`, `env`, `categories`, `globals`, `settings`) are shallow-merged; anything else replaces the base value.
- **`oxfmtConfig(overrides)`** — `ignorePatterns` and `overrides` are appended; every other key replaces the base value.
- **`eslintConfigs({ ignores, rules, vueRules, oxlint })`** — extra ignores, extra rules for all files, extra rules for `.vue` files only.

Pass the project's resolved oxlint config to `eslintConfigs({ oxlint })`. `eslint-plugin-oxlint` uses it to switch off in ESLint exactly the rules Oxlint already runs (and the rules Oxlint turns off), so the two never report the same thing twice.

::tip
To change a rule for **every** WOTZ project, change it upstream in `wotzebra/oxc-config`, then pull it in here:

```bash
pnpm update @wotzebra/oxc-config
```

Only put a rule in this repo's config when it's specific to this project.
::

::warning
`oxlint.config.ts` and `eslint.config.mjs` import files from `.nuxt/`. If lint fails with missing modules or odd type errors (e.g. `Argument of type 'keyof Collections' is not assignable to parameter of type 'never'` after a package update), regenerate them with `npx nuxt prepare`.
::

## Commands

```bash
pnpm run lint         # Oxlint (type-aware + type-check) then ESLint
pnpm run lint:fix     # Same, with --fix
pnpm run format       # Oxfmt write
pnpm run format:check # Oxfmt check without writing
```

Typical workflow: `pnpm run lint:fix && pnpm run format`.

Oxlint runs with `--type-aware --type-check`, so `pnpm run lint` also catches TypeScript errors.

## Oxfmt settings

The shared base:

```ts
{
	printWidth: 120,
	useTabs: true,
	tabWidth: 2,
	semi: true,
	singleQuote: true,
	trailingComma: 'none',
	singleAttributePerLine: true,
	bracketSameLine: true,
	sortImports: true,
	sortTailwindcss: true,
	vueIndentScriptAndStyle: true,
	ignorePatterns: ['package.json', 'package-lock.json', 'pnpm-lock.yaml', '*.md']
}
```

Notable choices:
- **`printWidth: 120`** — long lines wrap; the CSP arrays in `nuxt.config.ts` and long Drizzle chains end up one item per line.
- **`singleAttributePerLine` + `bracketSameLine`** — any element with more than one attribute puts each attribute on its own line, and the closing `>` / `/>` stays on the last attribute's line:
  ```vue
  <UButton
  	color="neutral"
  	variant="outline"
  	label="Cancel"
  	@click="isAddModalOpen = false" />
  ```
- **`vueIndentScriptAndStyle: true`** — indents the contents of `<script>` and `<style>` blocks in `.vue` files by one tab. Matches the ESLint `vue/script-indent` rule.
- **`sortImports` / `sortTailwindcss`** — import order and Tailwind class order are handled automatically.
- **Ignored files** — `package.json` and lockfiles are left alone (so `sortPackageJson` is not set), and `*.md` is skipped because oxfmt's markdown formatter turns MDC syntax (`::Component` + `---` YAML props) into headings and horizontal rules, corrupting content. This project adds `server/db/migrations`.

There's no `.oxfmtrc.json` or `.oxfmtignore` — ignores live in `ignorePatterns`.

`docs/` (this Docus site) and `presentation/` (the Slidev deck) are separate projects with their own `package.json`, so the root Oxlint, ESLint and Oxfmt configs all ignore them.

## ESLint (Vue rules only)

`eslintConfigs()` adds the Nuxt ESLint preset plus a few Vue-specific stylistic rules:

- `vue/script-indent` (tabs, `baseIndent: 1`)
- `vue/first-attribute-linebreak` (multiline: below)
- `vue/attribute-hyphenation` (`never` — use `:searchInput`, not `:search-input`)
- `vue/html-self-closing` (allows `<br />`, which is what oxfmt writes)

Rules that would fight oxfmt are switched off: `vue/html-indent`, `vue/max-attributes-per-line`, `vue/html-closing-bracket-newline`, `vue/singleline-html-element-content-newline`. Oxfmt owns indentation, attribute wrapping and bracket placement.

It also enables `jsonc` linting for JSON files (comments allowed in `tsconfig*.json`, `wrangler.jsonc` and `.vscode/*.json`).

If you're tempted to add a non-Vue rule to ESLint, check if Oxlint already has it first — almost everything does.

## When to add to optimizeDeps

If Vite logs "discovered new dependencies at runtime" for a package, add it to `vite.optimizeDeps.include` in `nuxt.config.ts` to silence the warning and prevent the one-time auto-reload. See [Vite dep duplication](/troubleshooting/vite-dep-duplication) for why `resolve.dedupe: ['vue']` is also needed.
