## Commands

```bash
pnpm run test         # Run every test once (what CI runs)
pnpm run test:watch   # Watch mode
npx vitest run --project unit   # Only the unit tests
npx vitest run --project nuxt   # Only the Nuxt tests
```

The deploy workflows run `npm test` before the build, so a failing test stops the deploy.

## Two projects

`vitest.config.ts` splits the tests by what they need:

| Project | Folder | Environment | For |
|---|---|---|---|
| **unit** | `test/unit/` | plain Node | Pure functions, schemas, server helpers. Starts in milliseconds. |
| **nuxt** | `test/nuxt/` | Nuxt app + happy-dom (`@nuxt/test-utils`) | Composables and components that need auto-imports, i18n, Nuxt UI. |

Prefer **unit** when the code doesn't need Nuxt — it's much faster and fails with clearer errors.

## Unit tests

Import app code with `@/…` and server code with `@@/server/…`:

```ts
import { usePhoneNumber } from '@/composables/usePhoneNumber';
import { validateTurnstile } from '@@/server/utils/turnstile';
```

Server code relies on Nitro's auto-imports (`createError`, `$fetch`, `useRuntimeConfig`, …), which don't exist in plain Node. Stub them per test:

```ts
import { createError } from 'h3';
import { afterEach, beforeEach, vi } from 'vitest';

beforeEach(() => {
	vi.stubGlobal('createError', createError);
	vi.stubGlobal('fetch', fetchMock);
	vi.stubEnv('NUXT_TURNSTILE_SECRET_KEY', 'secret-key');
});

afterEach(() => {
	vi.unstubAllGlobals();
	vi.unstubAllEnvs();
});
```

See `test/unit/turnstile.test.ts` for the full example.

## Nuxt tests

Tests in `test/nuxt/` run inside a real Nuxt app, so auto-imports (`useNuxtApp`, your composables, `#components`) just work. Mount components with `mountSuspended`:

```ts
import { mountSuspended } from '@nuxt/test-utils/runtime';

const wrapper = await mountSuspended(CLogo);
expect(wrapper.find('a').attributes('aria-label')).toBe('Who Owns The Zebra');
```

Composables that need a component context (anything using `useI18n`, lifecycle hooks or `watch` tied to a component) run inside a tiny wrapper component:

```ts
const Form = defineComponent({
	setup() {
		useZodLocale();
		return () => null;
	}
});

await mountSuspended(Form);
```

See `test/nuxt/useZodLocale.test.ts`.

::note
The Nuxt project boots the whole app, including `@nuxtjs/seo`, so the first run prints SEO warnings about SSR being disabled. They come from the test environment and can be ignored.
::

## Type-checking

`test/**/*` is in the root `tsconfig.json` include, so `pnpm run lint` (Oxlint with `--type-check`) also type-checks tests. If a test can't find an auto-import you just added, regenerate the types:

```bash
npx nuxt prepare
```
