## Tech stack

| Layer | Tool |
|---|---|
| Framework | Nuxt 4 (Nuxt 4 source root: `app/`) |
| UI | Nuxt UI v4 + Tailwind CSS v4 |
| Content | Nuxt Content v3 (locale-prefixed collections) |
| Content editing | Nuxt Studio (cloud editor talking to local dev) |
| i18n | `@nuxtjs/i18n` v10 (URL prefix strategy) |
| Database | Drizzle ORM + Cloudflare D1 / local SQLite in dev |
| Auth | `nuxt-auth-utils` (sessions, scrypt) |
| Deployment | Cloudflare Workers via NuxtHub + Wrangler |
| Lint/format | Oxlint + Oxfmt (ESLint kept for Vue stylistic rules) |
| Security | `nuxt-security` (CSP, rate limiting) |

## How a request flows

1. User hits `https://your-domain/nl/about`
2. **`@nuxtjs/i18n`** middleware detects the `/nl` prefix, sets locale state
3. **Vue Router** matches `app/pages/[...slug].vue` with `slug = ['about']`
4. The page calls `queryCollection('content_nl').path('/about').first()`
5. **Nuxt Content** runs the query against the local SQLite (dev) or D1 (prod)
6. Markdown is rendered via `<ContentRenderer :value="page" :data="page" />` — MDC components like `::u-page-hero` become Vue components
7. **`@nuxtjs/seo`** generates canonical tags, hreflang alternates, sitemap entry
8. **`nuxt-security`** adds CSP and other security headers to the response

## Critical Nitro preset detail

`nuxt.config.ts` sets the Nitro preset **conditionally**:

```ts
nitro: {
  preset: process.env.NODE_ENV === 'development' ? undefined : 'cloudflare_module'
}
```

Why: `@nuxt/content`'s `cloudflare` sub-preset (triggered by `preset: 'cloudflare_module'`) registers a `/__nuxt_content/{collection}/sql_dump.txt` handler that expects a Cloudflare `ASSETS` binding. In dev there's no `ASSETS`, so it returns an empty string and the client-side content DB stays empty — leading to blank pages on client-side navigation.

Using the default preset in dev makes `@nuxt/content` register its **node** sub-preset which reads the SQL dump from filesystem. The `cloudflare_module` preset is still active for `pnpm run build`.

See [Nitro preset & Content](/troubleshooting/nitro-preset-and-content) for the full debugging story.

## Vite optimizeDeps

`@vue/devtools-core` and `@vue/devtools-kit` bundle their own copy of `vue`, which causes duplicate Vue instances → `Cannot read properties of null (reading 'ce')` crashes. The fix lives in `nuxt.config.ts`:

```ts
vite: {
  resolve: { dedupe: ['vue'] },
  optimizeDeps: {
    include: ['@unhead/schema-org/vue', '@userback/widget', '@vue/devtools-core', '@vue/devtools-kit', 'zod', 'zod/locales']
  }
}
```

If Vite logs "discovered new dependencies at runtime" for a new package, add it to the include list. `resolve.dedupe` keeps the Vue copy safe.

## What's NOT included by design

- No state management library (Pinia, etc.) — `useState` is sufficient for the project's scale
- No client-side data fetching library — `useFetch` / `useAsyncData` are sufficient
- No CSS preprocessor — Tailwind v4 is enough
- No testing framework wired up yet — add Vitest when you have logic worth testing
