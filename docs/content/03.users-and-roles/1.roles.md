description: Who can see and do what, and where that's enforced.

| | Eigenaar (`owner`) | Huisgenoot (`member`) | Extern (`external`) |
|---|:-:|:-:|:-:|
| Overview, tasks, comments | ✓ | ✓ | own tasks only |
| Create / edit / delete tasks | ✓ | ✓ | status of own tasks only |
| Planning, floor plan, budget, files, contacts, settings | ✓ | ✓ | – |
| Upload photos to a task | ✓ | ✓ | own tasks only |
| Users, invites, Drive connection | ✓ | – | – |

An external's "own tasks" are tasks assigned to their **linked contact** (`users.contactId`) or to them as a user.

## Where it's enforced

The UI hides what you can't use, but the **server** is what decides:

| Guard | File | Used for |
|---|---|---|
| `requireUser` | `server/utils/auth.ts` | Any logged-in user; re-checks the session against the DB |
| `requireInternal` | `server/utils/auth.ts` | Owner or member |
| `requireOwner` | `server/utils/auth.ts` | Owner only |
| `taskVisibility(user)` | `server/utils/tasks.ts` | SQL condition added to every task query |
| `externalTaskUpdateSchema` | `shared/schemas/tasks.ts` | Externals may only send `{ status }` (strict) |
| `assertCanAccessEntity` / `assertCanAccessFile` | `server/utils/attachments.ts` | Attachments and Drive files |

On the client, `isInternal()` / `isOwner()` (`shared/utils/permissions.ts`) drive the navigation, and the `internal` route middleware sends externals back to `/taken`.

## Changing someone's role

Instellingen → Gebruikers. You can't lower your own role or delete yourself, so there's always an owner left. Role changes reach the other person's session on their next page load (the session is re-validated in `server/plugins/session.ts`).
