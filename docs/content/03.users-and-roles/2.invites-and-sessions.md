title: Invites & sessions
description: How people join, log in and stay logged in.

## Invites

There's no open registration. The owner creates an invite (Instellingen → Gebruikers → *Iemand uitnodigen*) with an e-mail address, optional name, role and — for externals — the contact to link.

- The server generates a random token and stores only its **SHA-256 hash** (`invites.tokenHash`). The plain link is shown **once** in the modal (copy it or open a pre-filled e-mail); it can't be displayed again.
- Links are valid for **14 days** (`INVITE_TTL_DAYS`) and can be revoked while unused.
- `/registreer?invite=…` looks the invite up (`GET /api/invites/lookup`), asks for a name and password, and `POST /api/auth/register` creates the account with the invite's e-mail, role and contact. If two tabs race on the same link, only the one that marks the invite as used keeps its account.

## Login

`POST /api/auth/login` requires a Cloudflare Turnstile token, then verifies the scrypt hash. Unknown e-mails take as long as wrong passwords and return the same message, so the form doesn't reveal which addresses exist. The endpoint is rate-limited to 10 requests per minute per IP.

## Sessions

`nuxt-auth-utils` keeps an encrypted session cookie (`NUXT_SESSION_PASSWORD`). The session stores `{ id, email, name, role, contactId }` plus `loggedInAt`.

Every API call (`requireUser`) and every session refresh (`server/plugins/session.ts`) re-reads the user from the database:

- a deleted user is logged out;
- a session older than the user's last password change (`users.passwordChangedAt`) is logged out;
- role or contact changes are picked up immediately.

Changing your password on `/account` sets `passwordChangedAt` and gives the current device a fresh session, so only your *other* devices are logged out.
