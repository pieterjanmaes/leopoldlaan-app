## The three categories

| Category | When used | Where (local) | Where (deployed) |
|---|---|---|---|
| **A. Build-time** (public, baked into client bundle) | During `nuxt build` | `.env` | GitHub Actions **repository variables** |
| **B. Runtime secrets** (server-only, sensitive) | At each request | `.env` | Cloudflare **Wrangler secrets** |
| **C. CI/CD** (not used by the app) | During GitHub Actions deploy | n/a | GitHub Actions **repository secrets/variables** |

The full annotated reference lives in `.env.example` at the project root. Copy it to `.env` for local dev.

## A. Build-time variables (public)

Embedded into the client JavaScript bundle. **Visible to anyone who views your site source** — only non-sensitive values belong here.

| Variable | Purpose |
|---|---|
| `NUXT_SITE_ENV` | `staging` or `production` — controls `robots.txt` |
| `NUXT_SITE_URL` | Public URL for SEO canonical, sitemap, OG images |
| `NUXT_PUBLIC_TURNSTILE_SITE_KEY` | Public Turnstile site key |
| `NUXT_PUBLIC_USERBACK_TOKEN` | Optional Userback widget token |
| `NUXT_PUBLIC_GOOGLE_TAG_MANAGER_ID` | Optional GTM container ID |

**Deploy via GitHub:** add as **repository variables** in `Settings → Secrets and variables → Actions → Variables`. The deploy workflows pass them to `nuxt build`.

## B. Runtime secrets (server-only)

Read by server endpoints at request time. **Never include real values in committed files or GitHub repo variables.**

| Variable | Purpose |
|---|---|
| `NUXT_SESSION_PASSWORD` | Session-cookie encryption (32+ random chars) |
| `NUXT_TURNSTILE_SECRET_KEY` | Server-side Turnstile verification |
| `NUXT_OG_IMAGE_SECRET` | OG image signing (`nuxt-og-image`) |
| `SEED_KEY` | Gate for `POST /api/seed` in non-dev environments |

**Deploy via Cloudflare Wrangler:**

```bash
wrangler secret put NUXT_SESSION_PASSWORD               # production
wrangler secret put NUXT_SESSION_PASSWORD --env preview # preview
# repeat for each runtime secret
```

Wrangler secrets are injected as Worker env vars at runtime. Nuxt's `runtimeConfig` reads them and overrides any defaults baked at build time.

You CAN mirror these as GitHub repo secrets if you want them as build-time defaults — but Cloudflare always wins at runtime, so it's optional.

## C. CI/CD variables

Used by the GitHub Actions workflows in `.github/workflows/`, not by the app.

| Variable | Where | Purpose |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | GitHub **secret** | Wrangler deploy auth (scope: Workers Scripts + D1) |
| `CLOUDFLARE_ACCOUNT_ID` | GitHub **variable** | Cloudflare account to deploy into |

## Local development

Copy `.env.example` → `.env` and fill in the test keys. All three categories live together in `.env` for local convenience; the split only matters for deployed environments.

```bash
cp .env.example .env
openssl rand -hex 32  # use the output as NUXT_SESSION_PASSWORD
```

## File reference

The `.env.example` file at the project root has heavy inline comments grouping every variable by category. Treat it as the canonical reference — if you add a new env var, update `.env.example` first.
