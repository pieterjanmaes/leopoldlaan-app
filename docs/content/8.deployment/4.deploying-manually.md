## When to deploy manually

- You're testing a deploy from a feature branch and don't want to merge to `preview` yet
- GitHub Actions is down or misconfigured
- You're seeding initial production data and want to deploy + verify before pushing to main
- Investigating a deploy-time issue and want fast iteration

For day-to-day work, **prefer the GitHub Actions flow** — it ensures environment vars are consistent and provides an audit trail.

## Prerequisites

1. `wrangler.jsonc` exists locally (copied from `wrangler.jsonc.example` with your IDs)
2. `.env.preview` and/or `.env.production` exist with the build-time vars filled in
3. You're logged into Wrangler: `wrangler login` (one-time)
4. All Wrangler secrets are already set on Cloudflare (`wrangler secret put ...`) — see [Cloudflare & Wrangler](/deployment/cloudflare-and-wrangler)

## Deploy commands

```bash
# Preview: build + deploy
pnpm run build:deploy:preview

# Production: build + deploy
pnpm run build:deploy:production

# Skip the build (use existing .output/)
pnpm run deploy:preview
pnpm run deploy:production
```

## What `build:deploy:*` does

```jsonc
"build:deploy:preview": "dotenv -e .env.preview -- pnpm run build && wrangler deploy --config wrangler.jsonc --env preview"
```

Step by step:
1. `dotenv -e .env.preview` loads the preview env vars
2. `pnpm run build` runs `nuxt build` with those vars (bakes Category A values into the bundle)
3. `wrangler deploy --config wrangler.jsonc --env preview` uploads to the preview Worker

Cloudflare provides the Category B secrets at runtime — they don't need to be in `.env.preview`.

## Verifying a manual deploy

```bash
# Quick health check
curl -I https://wotz-nuxt-starter-preview.workers.dev/nl
# → expect 200 OK

# Or the production URL
curl -I https://your-production-domain/nl
```

Then click around in the browser:
- Home page renders
- Language switcher works
- Sign-in works (sessions issued)
- Form submits without 500
- `/dashboard` shows seeded data

## Rolling back

Cloudflare keeps the last 10 deployments. To roll back:

```bash
npx wrangler deployments list
# → lists recent deploys with IDs

npx wrangler rollback <deployment-id>
```

Or use `dash.cloudflare.com → Workers & Pages → your worker → Deployments → Rollback`.

## Manual deploy gotchas

- **Stale `.output/`** — if you switched branches without running `pnpm run build`, the old `.output/` deploys. Always run `build:deploy:*` (which builds fresh) instead of `deploy:*` unless you know what's in `.output/`.
- **Env vars from your local `.env`** — `pnpm run build` (without `dotenv -e`) uses `.env` which is your DEV config. Always go through `build:deploy:preview` / `build:deploy:production`.
- **Wrangler secret missing** — the deploy succeeds but requests 500 with cryptic errors. Check `wrangler secret list --env preview` to confirm all secrets are present.
