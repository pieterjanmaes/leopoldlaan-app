## Stack

- **Cloudflare Workers** — runs the SSR Nuxt server (built with `nitro.preset: 'cloudflare_module'`)
- **Cloudflare D1** — the production SQLite database
- **NuxtHub** (`@nuxthub/core`) — glue layer that provides the `hub:db` import, auto-runs migrations, and configures the D1 binding

## `wrangler.jsonc`

Each environment (production, preview) has its own Worker config:

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "wotz-nuxt-starter",
  "compatibility_date": "2026-04-02",
  "compatibility_flags": ["nodejs_compat"],
  "main": ".output/server/index.mjs",
  "account_id": "YOUR_CLOUDFLARE_ACCOUNT_ID",

  "assets": { "directory": ".output/public", "binding": "ASSETS" },

  "d1_databases": [
    { "binding": "DB", "database_name": "wotz-nuxt-starter", "database_id": "YOUR_D1_ID" }
  ],

  "vars": {
    "NUXT_SITE_ENV": "production",
    "NUXT_SITE_URL": "https://your-domain"
  },

  "env": {
    "preview": {
      "name": "wotz-nuxt-starter-preview",
      "d1_databases": [
        { "binding": "DB", "database_name": "wotz-nuxt-starter-preview", "database_id": "YOUR_PREVIEW_D1_ID" }
      ],
      "vars": {
        "NUXT_SITE_ENV": "staging",
        "NUXT_SITE_URL": "https://wotz-nuxt-starter-preview.workers.dev"
      }
    }
  }
}
```

::warning
`wrangler.jsonc` is **gitignored** because it contains your account ID and database IDs. Use `wrangler.jsonc.example` as the template, copy it on each fresh clone, and fill in your IDs.
::

## Setting up Cloudflare for the first time

1. Create a Cloudflare account
2. Get your account ID from the dashboard sidebar
3. Create D1 databases:
   ```bash
   npx wrangler d1 create wotz-nuxt-starter
   npx wrangler d1 create wotz-nuxt-starter-preview
   ```
4. Copy the `database_id` values from each into `wrangler.jsonc`
5. Create an API token at `dash.cloudflare.com → My Profile → API Tokens` with `Workers Scripts:Edit` + `D1:Edit` scopes — save for the GitHub `CLOUDFLARE_API_TOKEN` secret

## Setting runtime secrets

Cloudflare Workers env vars come from two places:
- `vars` in `wrangler.jsonc` — non-sensitive, visible
- `wrangler secret put X` — sensitive, encrypted

For the runtime secrets list (see [Environment variables](/deployment/environment-variables) — Category B):

```bash
wrangler secret put NUXT_SESSION_PASSWORD               # production
wrangler secret put NUXT_SESSION_PASSWORD --env preview # preview

wrangler secret put NUXT_TURNSTILE_SECRET_KEY
wrangler secret put NUXT_TURNSTILE_SECRET_KEY --env preview

wrangler secret put NUXT_OG_IMAGE_SECRET
wrangler secret put NUXT_OG_IMAGE_SECRET --env preview

# SEED_KEY only if you want /api/seed accessible in deployed environments
wrangler secret put SEED_KEY
wrangler secret put SEED_KEY --env preview
```

Each `wrangler secret put` prompts for the value interactively.

## How the build runs on Cloudflare

1. `pnpm run build` produces `.output/` (server bundle + public assets)
2. `wrangler deploy` uploads:
   - `.output/server/index.mjs` as the Worker script
   - `.output/public/*` as static assets (served via the `ASSETS` binding)
3. On first request, the Worker boots, NuxtHub auto-applies any pending D1 migrations, and serves the response

## Inspecting production data

```bash
# List rows in a table
npx wrangler d1 execute DB --command "SELECT * FROM form_submissions LIMIT 10;"

# Use --env preview for the preview database
npx wrangler d1 execute DB --env preview --command "SELECT * FROM users;"
```

For an interactive UI, use the **D1 console in the Cloudflare dashboard**: `dash.cloudflare.com → Workers & Pages → D1 → your database → Console`.

## Costs

Workers free tier covers 100K requests/day, D1 free tier covers 5M row reads/day and 100K writes/day. Plenty for the starter's typical workload. Past that you're on the paid tier (~$5/month base).
