## The three workflows

`.github/workflows/` contains:

| File | Triggers on | Deploys to |
|---|---|---|
| `deploy-preview.yml` | push to `preview` branch | preview Worker |
| `deploy-preprod.yml` | push to `preprod` branch | preprod Worker |
| `deploy-prod.yml` | push to `main` branch, or `sanity-publish` repository_dispatch | production Worker |

Each environment uses a [GitHub Environment](https://docs.github.com/en/actions/deployment/targeting-different-environments/using-environments-for-deployment) with its own protection rules (required approvals, branch restrictions).

## What each workflow does

```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production  # or preview / preprod
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'pnpm'

      - run: pnpm install
      - run: npx nuxt prepare

      - name: Test
        run: npm test  # Vitest — a failing test stops the deploy

      - name: Build Nuxt
        run: npm run build
        env:
          NODE_OPTIONS: --max-old-space-size=4096
          NUXT_SITE_ENV: production
          NUXT_SITE_URL: ${{ vars.NUXT_SITE_URL }}
          NUXT_SESSION_PASSWORD: ${{ secrets.NUXT_SESSION_PASSWORD }}
          NUXT_TURNSTILE_SECRET_KEY: ${{ secrets.NUXT_TURNSTILE_SECRET_KEY }}
          SEED_KEY: ${{ secrets.SEED_KEY }}
          NUXT_PUBLIC_TURNSTILE_SITE_KEY: ${{ vars.NUXT_PUBLIC_TURNSTILE_SITE_KEY }}
          NUXT_PUBLIC_USERBACK_TOKEN: ${{ vars.NUXT_PUBLIC_USERBACK_TOKEN }}

      - name: Deploy to Cloudflare
        run: npx wrangler deploy --config wrangler.jsonc
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ vars.CLOUDFLARE_ACCOUNT_ID }}
```

## Required GitHub repo secrets/variables

**Secrets** (`Settings → Secrets and variables → Actions → Secrets`):
- `CLOUDFLARE_API_TOKEN` — your Cloudflare API token
- `NUXT_SESSION_PASSWORD` — passed at build time as fallback default
- `NUXT_TURNSTILE_SECRET_KEY` — same
- `SEED_KEY` — same (optional)
- `NUXT_OG_IMAGE_SECRET` — same (optional)

**Variables** (`Settings → Secrets and variables → Actions → Variables`):
- `CLOUDFLARE_ACCOUNT_ID` — your Cloudflare account ID
- `NUXT_SITE_URL` — environment-specific URL (set per Environment)
- `NUXT_PUBLIC_TURNSTILE_SITE_KEY`
- `NUXT_PUBLIC_USERBACK_TOKEN`
- `NUXT_PUBLIC_GOOGLE_TAG_MANAGER_ID`

Per-environment overrides go in the Environment-scoped vars/secrets, not the repo-wide ones.

## Why both build-time AND Wrangler secrets for the same value?

Build-time `NUXT_SESSION_PASSWORD` gets baked into the Worker bundle as the default. Cloudflare-level secrets injected at runtime override it. Mirroring isn't strictly necessary — Cloudflare wins anyway — but it gives a sensible fallback if a Wrangler secret is accidentally missing.

For pure simplicity, you can leave the Cat-B secrets out of GitHub entirely and rely on Wrangler exclusively. The build will warn that `runtimeConfig.session.password` is unset, then Cloudflare provides it at runtime.

## Triggering a deploy

```bash
# Preview
git push origin preview

# Preprod
git push origin preprod

# Production
git push origin main
```

Or trigger via the GitHub UI: `Actions → choose workflow → Run workflow`.

For prod, there's also a `repository_dispatch: sanity-publish` trigger so a Sanity webhook (if you add Sanity integration later) can fire a redeploy.

## Verifying a deploy

The workflow output ends with `wrangler deploy`'s response, which includes the Worker URL. Visit it; check:
- HTTP 200 on the home page
- Sign-in works (sessions issued correctly)
- Form submits without 500
- D1 query returns rows (`/dashboard` should list any submissions)
