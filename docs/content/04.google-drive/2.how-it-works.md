## Connection

`server/routes/auth/google-drive.get.ts` wraps `defineOAuthGoogleEventHandler` from `nuxt-auth-utils`:

- only an owner may start it (`requireOwner`);
- it asks for `access_type=offline` and `prompt=consent`, because Google only returns a **refresh token** when the consent screen is shown;
- on success it does **not** touch the user's session; it stores the Google account in `drive_connection` (a single row, `id = 'main'`) and redirects to `/instellingen?drive=connected`.

## Token storage

The refresh token is encrypted with **AES-GCM** (random 12-byte IV per encryption, key = SHA-256 of `NUXT_DRIVE_TOKEN_KEY`) in `server/utils/crypto.ts`. The short-lived access token and its expiry are cached in the same row and refreshed a minute before they expire. If Google refuses the refresh (revoked access, or a consent screen still in *Testing*), the API answers **409 "koppel opnieuw"**.

## The Drive wrapper

`server/utils/drive.ts` calls Drive REST v3 with `fetch` — no `googleapis` SDK, which is far too heavy for a Worker.

| Function | Does |
|---|---|
| `listDriveFolder` | Lists a folder (folders first, paginated up to 1000 items) |
| `getDriveFile` | Metadata incl. parents and thumbnail link |
| `createDriveFolder` | Creates a folder |
| `uploadDriveFile` | **Resumable** upload: one call for metadata, one `PUT` for the bytes |
| `fetchDriveContent` / `fetchDriveThumbnail` | Streams the file / a 400 px thumbnail |
| `pathFromRoot` | Walks up the parents to build breadcrumbs and to check a file is inside the project folder |

Uploads are capped at **50 MB per file**; Workers accept request bodies up to 100 MB.

## Access checks

Downloads and thumbnails go through `/api/drive/files/:id/content` and `/thumbnail`, never straight to Google. `assertCanAccessFile` decides:

- **Household**: the file must be attached somewhere, or sit inside the project folder. Folder listings remember their file ids for 10 minutes, so a page of thumbnails doesn't walk the tree once per image.
- **Externals**: the file must be attached to a task they can see.

This keeps the rest of the connected Google account private, even though the OAuth scope covers the whole Drive.

## Attachments

`attachments` links a Drive file id to an entity (`task`, `quote`, `expense`, …) and caches its name, type, size and Drive link. Deleting a task, quote or invoice removes its attachment rows; the files stay in Drive. Disconnecting Drive keeps the rows, so reconnecting the same account restores every link.
