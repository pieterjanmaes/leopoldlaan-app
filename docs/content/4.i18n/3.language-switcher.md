## The component

`app/components/CLanguageSwitcher.vue` renders a `<USelectMenu>` listing the available locales and navigates when the user picks one.

```vue
<template>
  <USelectMenu
    :modelValue="locale"
    :items="Object.values(locales)"
    valueKey="code"
    labelKey="name"
    color="neutral"
    variant="ghost"
    icon="heroicons:globe-alt"
    arrow
    :searchInput="false"
    class="w-38"
    @update:modelValue="switchLocale($event)"
  />
</template>

<script setup lang="ts">
const { locale, locales } = useI18n();
const router = useRouter();

const translatedPaths = useState<Record<string, string>>('translatedPaths', () => ({}));

function switchLocale(targetLocale: string) {
  const translatedPath = translatedPaths.value[targetLocale];
  if (translatedPath) {
    router.push(translatedPath);
  } else {
    const currentPath = router.currentRoute.value.path;
    const pathWithoutLocale = currentPath.replace(/^\/[a-z]{2}(\/|$)/, '/');
    const newPath = `/${targetLocale}${pathWithoutLocale === '/' ? '' : pathWithoutLocale}`;
    router.push(newPath);
  }
}
</script>
```

## How it picks the URL

The switcher reads a shared `translatedPaths` state populated by the catch-all page:

1. **Catch-all page** runs `useTranslatedPath().getAllTranslatedPaths(canonicalId)` after loading the current content
2. The result (e.g. `{ nl: '/cookie-policy', fr: '/politique-cookies' }`) is written to `useState('translatedPaths')`
3. **Switcher** reads from that state — `translatedPaths.value['fr']` gives the matching FR URL
4. `router.push(translatedPath)` navigates

If the state isn't populated (e.g. on a non-content page like `/dashboard`), the switcher falls back to a simple locale-prefix swap: `/nl/dashboard` → `/fr/dashboard`.

## Why a shared state, not props?

The switcher lives in `<CHeader>`, which is rendered by the layout — not the page. Passing props down through the layout would require either a layout slot or a wrapping component. `useState` keeps the switcher decoupled.

## When the URL has no canonicalId match

If the user is on `/nl/cookie-policy` and `cookie-policy` exists in NL but NOT in FR (no FR file with `canonicalId: cookie-policy`), `getTranslatedPath('fr', 'cookie-policy')` falls back to a literal slug swap — returns `/fr/cookie-policy` — which then 404s in FR.

Two ways to handle this:
- Create the FR translation
- Wrap the switcher to detect missing translations and grey out the option (not currently implemented)

## Don't use `setLocale()`

Earlier versions of this component used `@nuxtjs/i18n`'s `setLocale()`, but that doesn't respect canonical translation — it just adds the locale prefix to the current path. Use `router.push(translatedPath)` instead.
