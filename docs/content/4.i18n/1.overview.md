## Configuration

`@nuxtjs/i18n` v10 is configured in `nuxt.config.ts`:

```ts
i18n: {
  baseUrl: process.env.SITE_URL,
  defaultLocale: 'nl',
  locales: [
    { code: 'nl', language: 'nl-BE', name: 'Nederlands', file: 'nl.json' },
    { code: 'fr', language: 'fr-BE', name: 'Francais', file: 'fr.json' }
  ],
  strategy: 'prefix',
  rootRedirect: { path: 'nl', statusCode: 302 },
  langDir: 'locales/',
  vueI18n: './i18n.config.ts',
  detectBrowserLanguage: false
}
```

## Key choices

| Setting | Value | Why |
|---|---|---|
| `strategy` | `'prefix'` | Every URL has a locale prefix (`/nl/...`, `/fr/...`). No magic locale-from-cookie behavior. |
| `defaultLocale` | `'nl'` | Dutch is the primary audience. |
| `rootRedirect` | `/nl` (302) | `/` redirects to the default locale's home. Temporary redirect so you can swap later. |
| `detectBrowserLanguage` | `false` | Visitors choose their language explicitly via the switcher — no surprise redirects. |
| `language` | `'nl-BE'`, `'fr-BE'` | Belgium variants. Affects the `lang` attribute on `<html>` and hreflang tags. |

## Translation strings

UI strings (button labels, error messages) live in `i18n/locales/{locale}.json`. The schema is identical across locales — Vue I18n complains if a key is missing in one.

```json [i18n/locales/nl.json]
{
  "error": {
    "pageNotFound": "Pagina niet gevonden"
  }
}
```

```json [i18n/locales/fr.json]
{
  "error": {
    "pageNotFound": "Page non trouvée"
  }
}
```

Use them in components:

```vue
<script setup lang="ts">
const { t } = useI18n();
</script>

<template>
  <h1>{{ t('error.pageNotFound') }}</h1>
</template>
```

## Content vs translations

Two separate systems:
- **Translation strings** (`i18n/locales/*.json`) — for UI labels reused across pages
- **Page content** (`content/{locale}/*.md`) — for full pages with their own copy

Don't put marketing copy in translation JSON; it belongs in markdown so non-devs can edit it via Studio.

## Routes after i18n is applied

| File | URL (NL) | URL (FR) |
|---|---|---|
| `app/pages/[...slug].vue` (matches `/about`) | `/nl/about` | `/fr/about` |
| `app/pages/dashboard/index.vue` | `/nl/dashboard` | `/fr/dashboard` |

The dashboard pages get the locale prefix too. If you want them to live at a single non-localized URL, opt them out with `defineI18nRoute(false)` in the page setup — but be aware that `navigateTo` from i18n will still try to add a prefix, requiring `localePath()` workarounds.
