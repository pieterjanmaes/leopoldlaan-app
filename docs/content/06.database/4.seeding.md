`POST /api/seed` (`server/api/seed.post.ts`) prepares an empty database.

```bash
curl -k -X POST https://localhost:3000/api/seed         # owner + structure
curl -k -X POST 'https://localhost:3000/api/seed?demo'  # + demo budget (dev only)
```

## What it creates

1. **Owner** — `SEED_OWNER_EMAIL` / `SEED_OWNER_PASSWORD` / `SEED_OWNER_NAME`, defaulting to `eigenaar@leopoldlaan.test` / `changeme123` / `Eigenaar`. Skipped when the e-mail exists.
2. **Structure** — only when there are no categories and no phases yet:
   - 15 werkposten from *Sloop & afbraak* to *Administratie & premies*;
   - rooms per floor (gelijkvloers, eerste verdieping, zolder, kelder, buiten);
   - five phases spread over ~26 weeks from today, each with starter tasks, chained so every task waits on the previous one;
   - milestones *Keuring elektriciteit (AREI)* and *Verhuis*;
   - two empty *Mijn VerbouwPremie* subsidies.
3. **Demo** (`?demo`, dev only) — a contractor, five budget lines, an approved roofing quote and a 30% advance invoice.

## Access

In development the endpoint is open. Elsewhere it requires the `x-seed-key` header to match the `SEED_KEY` secret, and refuses when `SEED_KEY` isn't set:

```bash
curl -X POST -H "x-seed-key: $SEED_KEY" https://<domain>/api/seed
```

Set `SEED_OWNER_EMAIL` and `SEED_OWNER_PASSWORD` as Wrangler secrets **before** seeding a deployed database, then change the password on `/account` after the first login.
