The schema is in `server/db/schema.ts` (Drizzle, SQLite dialect). Row types are exported from `server/utils/drizzle.ts` (`Task`, `Quote`, …) together with `tables` and the query operators.

## Conventions

| Kind of value | Column type | Why |
|---|---|---|
| Ids | `text`, CUID2 (`id()` helper) | Unguessable, sortable enough, no auto-increment races |
| Money | `integer` **cents** | No floating-point rounding (`0.1 + 0.2`) |
| Calendar dates | `text` `'YYYY-MM-DD'` | A date is a day, not a moment — no timezone shifts |
| Moments | `integer` timestamp (`createdAt()`, `updatedAt()`) | Real points in time |
| Enums | `text` with `enum:` from `shared/utils/constants.ts` | One list for schema, validation and UI |
| Points on a plan | `text` JSON (`[x, y][]`, 0..1) | Size-independent marker positions |

Foreign keys use `onDelete: 'set null'` for optional links (a deleted room doesn't delete its tasks) and `cascade` for owned children (comments, dependencies, plan markers).

## Tables

| Table | Holds |
|---|---|
| `users` | Login, name, `role` (`owner` / `member` / `external`), optional `contactId`, `passwordChangedAt` |
| `project` | Single row (`id = 'main'`): name, address, dates, contingency %. Created on first read |
| `rooms`, `categories`, `phases` | Catalogs; categories have colour + icon, phases can be milestones |
| `contacts` | Contractors, suppliers, … |
| `tasks` | Status, priority, room, category, phase, assignee (user **or** contact), start/due date, `doneAt`, sort order |
| `task_dependencies` | `taskId` waits on `dependsOnTaskId` |
| `task_comments` | Comments, also by externals |
| `budget_lines` | Planned amounts per category/room |
| `quotes` | Amount excl. VAT + rate + status |
| `expenses` | Invoices: excl., rate, **stored** incl. total, dates, payment |
| `subsidies` | Expected/received amounts, status, deadline |
| `drive_connection` | Single row: Google account, encrypted refresh token, cached access token, project folder |
| `attachments` | Drive file ↔ entity (`task`, `quote`, `expense`, …), unique per entity + file |
| `invites` | E-mail, role, contact, hashed token, expiry, used by/at |
| `floor_plans`, `plan_markers` | Floors with a background, zones and pins |
| `decisions` | Open or settled choices: status, deadline, decided on/by, room, category, task, contact, reference |

## Querying

```ts
import { db } from 'hub:db';

import { and, eq, tables } from '../utils/drizzle';

const open = await db
  .select()
  .from(tables.tasks)
  .where(and(eq(tables.tasks.status, 'todo'), taskVisibility(user)));
```

Always add `taskVisibility(user)` to task queries so externals stay limited to their own tasks. For lists of ids, prefer reading the (small) table and filtering in code over large `inArray` lists — D1 limits the number of bound parameters per query.
