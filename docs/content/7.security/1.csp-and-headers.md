## What `nuxt-security` does

The module adds HTTP security headers to every response:
- **Content-Security-Policy** — restricts what scripts/styles/connections the page can load
- **Cross-Origin Resource Policy** / **Cross-Origin Embedder Policy** — control resource isolation
- **X-Frame-Options**, **X-Content-Type-Options**, **Strict-Transport-Security**, etc.
- **Rate limiting** middleware on top of that

It also runs a `xssValidator` middleware on GET/POST that rejects requests with suspicious-looking payloads.

## Current config

```ts [nuxt.config.ts]
security: {
  rateLimiter: false,  // disabled globally; enabled per-route below
  ssg: false,          // we SSR via Cloudflare, not generate
  headers: {
    crossOriginResourcePolicy: 'cross-origin',
    crossOriginEmbedderPolicy: 'unsafe-none',
    contentSecurityPolicy: {
      'font-src': ["'self'", 'https:', '*.cloudflare.com', '*.cookiefirst.com'],
      'img-src': ["'self'", 'data:', 'https:', '*.googletagmanager.com', '*.google-analytics.com', '*.cookiefirst.com'],
      'script-src': ["'self'", "'unsafe-inline'", "'unsafe-eval'", '*.googletagmanager.com', '*.cloudflare.com', '*.cookiefirst.com'],
      'style-src': ["'self'", "'unsafe-inline'", '*.cookiefirst.com'],
      'connect-src': ["'self'", 'https:', 'http:', '*.googletagmanager.com', '*.google-analytics.com', '*.cookiefirst.com'],
      'media-src': ["'self'", 'https:'],
      'frame-src': ["'self'", '*.googletagmanager.com', '*.cloudflare.com', '*.cookiefirst.com'],
      'object-src': ["'none'"],
      'base-uri': ["'self'"]
    }
  }
}
```

## Why each directive looks the way it does

| Directive | Choice | Reason |
|---|---|---|
| `script-src` `'unsafe-inline'` | allowed | Nuxt's hydration runtime injects inline scripts; can't be removed without breaking hydration |
| `script-src` `'unsafe-eval'` | allowed | Some third-party widgets (Nuxt Studio's edit-mode loader, GTM) need `eval` |
| `script-src` `*.cloudflare.com` | allowed | Turnstile loads its script from Cloudflare |
| `script-src` `*.googletagmanager.com` | allowed | GTM container (optional, gated by `NUXT_PUBLIC_GOOGLE_TAG_MANAGER_ID`) |
| `style-src` `'unsafe-inline'` | allowed | Vue scoped styles are inlined as `<style>` tags |
| `connect-src` `https:` / `http:` | wide open | Nuxt Studio talks to `nuxt.studio` + `content.nuxt.com`; tightening would require explicit allowlist |
| `img-src` `https:` | wide open | Editorial content can reference any HTTPS image |
| `frame-ancestors` | (not set) | Default allows same-origin framing, which Nuxt Studio's preview needs |
| `font-src` `*.cookiefirst.com` | allowed | CookieFirst's consent banner loads its font |

## What's relaxed for Cloudflare + Studio

- **`crossOriginResourcePolicy: 'cross-origin'`** — lets external resources (fonts, scripts) load from third-party domains. Default `'same-origin'` blocks fonts from Google Fonts and similar.
- **`crossOriginEmbedderPolicy: 'unsafe-none'`** — required when loading resources without `Cross-Origin-Resource-Policy` headers (which is most third-party stuff).
- **No `frame-ancestors`** — relies on the default (`'self'` implicit). If you add `frame-ancestors` explicitly, you also need to include `https://nuxt.studio` and `https://*.nuxt.studio` for Studio's preview iframe.

## What's intentionally turned off

- **`rateLimiter: false`** — global rate limiting is too coarse; we apply it only to `/api/*` (see [Rate limiting](/security/rate-limiting))
- **`ssg: false`** — SSG hash generation only matters for `nuxt generate`; we use SSR via Cloudflare Workers

## Tightening the CSP later

When you have a moment, the security wins:
- **Remove `'unsafe-inline'` from `script-src`** — requires moving Nuxt's inline scripts to `nonce`-based approval. Nuxt-security has nonce support (`nonce: true` in its config), but you need to verify every inline script gets the nonce attached.
- **Remove `'unsafe-eval'`** — requires identifying every consumer (likely Studio + GTM) and either dropping them or finding eval-free alternatives.
- **Narrow `connect-src`** from `https:` to specific domains — list every domain Studio/GTM/Analytics talks to. Painful but possible.

Each tightening must be retested in dev (especially Studio) before deploying.
