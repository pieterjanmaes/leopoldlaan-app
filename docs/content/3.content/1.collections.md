## The pattern

This project uses **one Nuxt Content collection per locale**, with content paths that **do not contain the locale prefix**. The locale prefix is added at the URL routing level by `@nuxtjs/i18n`.

```ts [content.config.ts]
import { defineContentConfig, defineCollection, z } from '@nuxt/content';

const pageSchema = z.object({
  canonicalId: z.string().optional(),
  title: z.string(),
  description: z.string().optional()
});

export default defineContentConfig({
  collections: {
    content_nl: defineCollection({
      type: 'page',
      source: { include: 'nl/**/*.md', prefix: '/' },
      schema: pageSchema
    }),
    content_fr: defineCollection({
      type: 'page',
      source: { include: 'fr/**/*.md', prefix: '/' },
      schema: pageSchema
    })
  }
});
```

## Why `prefix: '/'`?

A file at `content/nl/cookie-policy.md` is **stored in the collection with path `/cookie-policy`** — not `/nl/cookie-policy`. The `/nl` part is owned by the i18n router.

At runtime, the catch-all page queries the locale-specific collection with the locale-agnostic path:

```ts
const collection = ('content_' + locale.value) as keyof Collections;
const content = await queryCollection(collection).path(slug.value).first();
// e.g. queryCollection('content_nl').path('/cookie-policy').first()
```

## Adding new pages

1. Drop a markdown file into `content/nl/` (and its translation into `content/fr/`)
2. Use matching `canonicalId` frontmatter in both — see [canonicalId](/content/canonical-ids)
3. Restart dev server (Nuxt Content rebuilds the manifest on collection change)
4. Page is reachable at `/nl/your-file-name` and `/fr/your-file-name`

```md
---
canonicalId: about
title: Over ons
description: Wie zijn wij?
---

# Over ons

::u-page-section
Welkom op onze pagina.
::
```

## Why two collections instead of one?

A single collection with `nl/about.md` and `fr/about.md` would work but means:
- You have to filter by language in every query (`.where('path', 'like', '/nl/%')`)
- Studio's sidebar shows all locales mixed together
- Path collisions are easy when you forget the locale folder

Two collections give you clean per-locale scoping at the price of one extra `defineCollection` call.

## DO NOT do this

::warning
**Don't put the locale in the URL prefix:**
```ts
source: { include: 'nl/**/*.md', prefix: '/nl' }  // WRONG
```
This produces content paths like `/nl/cookie-policy`. Combined with the i18n router also adding `/nl`, you'd need URLs like `/nl/nl/cookie-policy` to match — and you'd hit Nuxt Studio bug [#423](https://github.com/nuxt-content/nuxt-studio/issues/423) (prefixed-collection index collision).
::

## DO NOT do this either

::warning
**Don't use `cwd` to point at the locale folder:**
```ts
source: { include: '**/*.md', cwd: 'content/nl', prefix: '/' }  // BREAKS STUDIO
```
Both collections produce an `index.md` at the same filesystem path under `cwd`, which trips the same `path collision` bug. Always use `include: 'nl/**/*.md'` with no `cwd`.
::
