## File format

Content lives in `content/{locale}/*.md`. Every file needs three frontmatter fields:

```md
---
canonicalId: about
title: Over ons
description: Een korte uitleg over wie we zijn.
---
```

| Field | Required | Purpose |
|---|---|---|
| `canonicalId` | recommended | Links translations together — see [canonicalId](/content/canonical-ids) |
| `title` | yes | Page title — also used in `<title>` and OG tags |
| `description` | yes | Meta description |

The schema is enforced by `content.config.ts`. Missing fields cause a build error.

## MDC components — always YAML props

Inside markdown you can embed Vue components via MDC syntax. **Use YAML frontmatter for props, not inline attributes.**

```md
::u-page-hero
---
orientation: horizontal
title: Welkom
description: Een korte intro
links:
  - label: Lees meer
    to: /over
    variant: solid
---
::
```

Why YAML? The Studio editor only round-trips YAML props cleanly, and the Vite MDC parser is more reliable with YAML than with inline attribute strings.

## Slot content

Slots go between the opening `::` and closing `::`:

```md
::u-page-section
---
title: Onze waardes
---

Hier komt de slot-inhoud — kan ook gewone markdown zijn.

- punt 1
- punt 2
- punt 3
::
```

Named slots use `#slot-name`:

```md
::u-page-hero
#title
Welkom

#description
Een lange beschrijving die kan **vetgedrukt** of _cursief_ zijn.
::
```

## Nesting

Each level of nesting adds a colon:

```md
::u-page-section
---
title: Outer section
---

  :::u-page-c-t-a
  ---
  title: Inner CTA
  ---
    ::::u-card
    Card inside the CTA inside the section.
    ::::
  :::
::
```

The colon count must match between opening and closing.

## Inline components

Use a single colon for inline (no children) components:

```md
Een :u-icon{name="i-lucide-info"} icoon in een zin.
```

## Common gotchas

::callout{icon="i-lucide-alert-triangle" color="warning"}
**Component name casing**: in MDC, components are kebab-cased. `<UPageHero>` becomes `::u-page-hero`. `<CForm>` becomes `:c-form`.
::

::callout{icon="i-lucide-alert-triangle" color="warning"}
**Indentation matters**: nested MDC components must be indented with **2 spaces** (not tabs) for the parser to detect the nesting. This is the one place in the codebase where you should use spaces.
::
